Learn About Hashing & Security

Build a solid foundation in cryptographic concepts, hash analysis, and modern security practices.

🧩

What Is a Hash?

A hash function is a mathematical algorithm that takes an input (or “message”) of any size and produces a fixed-size string of characters, known as the hash value, digest, or checksum.

Key Properties

🔒 One-Way

It is computationally infeasible to reverse a hash back to the original input. You cannot “decrypt” a hash.

📏 Fixed Length

Regardless of the input size, the output hash is always the same length. An MD5 hash is always 32 hexadecimal characters.

🔄 Deterministic

The same input always produces the same hash. This makes hashes useful for data verification and integrity checks.

⚡ Avalanche Effect

A small change in the input produces a dramatically different hash. Even changing a single character creates an entirely new digest.

Example

Input: "hello"
MD5 Hash: 5d41402abc4b2a76b9719d911017c592
Input: "Hello"
MD5 Hash: 8b1a9953c4611296a827abf8c47804d7

Notice how changing just the capitalization of the first letter produces a completely different hash.

🗝️

What Is MD5?

MD5 (Message-Digest Algorithm 5) is a widely known hash function designed by Ronald Rivest in 1991. It produces a 128-bit (16-byte) hash value, typically rendered as a 32-character hexadecimal string.

Property Value
Output Size 128 bits (32 hex characters)
Block Size 512 bits
Year Introduced 1991
Designer Ronald Rivest
Status Cryptographically Broken

Why Is MD5 Considered Insecure?

  • Collision Vulnerability: Researchers demonstrated practical collision attacks as early as 2004, meaning two different inputs can produce the same MD5 hash.
  • Speed: MD5 is extremely fast to compute, which makes brute-force and dictionary attacks feasible against hashed passwords.
  • Rainbow Tables: Pre-computed lookup tables exist for billions of common MD5 hashes, enabling near-instant reversal of unsalted hashes.
Important: MD5 should never be used for password hashing or security-critical applications. It remains relevant only for non-security purposes like checksums for file integrity verification.

Hashing vs Encryption vs Encoding

These three concepts are frequently confused but serve fundamentally different purposes. Understanding their distinctions is crucial for cybersecurity literacy.

🔒 Hashing

Hashing transforms data into a fixed-size digest. It is a one-way process — you cannot recover the original data from the hash alone. Hashing is used to verify data integrity, store passwords securely, and create digital signatures.

🔐 Encryption

Encryption transforms data into ciphertext using a key. It is a two-way process — authorized parties with the correct key can decrypt the data back to its original form. Encryption protects data confidentiality during storage and transmission.

📦 Encoding

Encoding transforms data into a different format for safe transport or storage. It is freely reversible and provides no security. Common examples include Base64 encoding for binary data in text formats and URL encoding for special characters.

Key Takeaway: Encoding is not encryption. Base64 is not a security measure. If you need to protect data, use encryption. If you need to verify data, use hashing.

How Hash Lookup Works

Hash lookup (sometimes called “hash reversal” or “hash cracking”) is the process of finding the original input that produces a given hash. Since hash functions are one-way, this is done through lookup databases rather than mathematical reversal.

Step-by-Step Process

  1. Hash Submission: The user provides a hash value (e.g., an MD5 digest) to the lookup service.
  2. Database Search: The service checks its database of pre-computed hash-to-plaintext mappings. These databases contain billions of entries generated from dictionaries, common passwords, and pattern-based wordlists.
  3. Match Check: If the hash exists in the database, the corresponding plaintext is returned. If not, the service reports that no match was found.
  4. Result Interpretation: A “found” result means the hash corresponds to a known plaintext. A “not found” result means the plaintext is not in the service’s database — it does not mean the hash is uncrackable.

Salted Password Hashes

A salt is a random value added to a password before hashing. The salt ensures that identical passwords produce different hashes, defeating pre-computed lookup tables and rainbow table attacks.

How Salting Works

Password: "mypassword"
Salt: "x8Kp2mQz"
Combined: "x8Kp2mQzmypassword"
Hash: a7f2c8e1... (unique to this salt)

Why Salts Matter

  • Unique Hashes: Even if two users have the same password, their hashes will be different because each has a unique salt.
  • Rainbow Table Resistance: Pre-computed tables become useless because the attacker would need a separate table for every possible salt value.
  • Brute-Force Isolation: An attacker must crack each hash individually rather than attacking all hashes simultaneously.
Best Practice: Always use a unique, cryptographically random salt for each password. The salt does not need to be secret — it is typically stored alongside the hash.

Modern Password Storage

Modern applications do not use simple hash functions like MD5 or SHA-256 for password storage. Instead, they use specialized password hashing functions designed to be slow, memory-intensive, and resistant to hardware-accelerated attacks.

🏆 Argon2id

Recommended

Winner of the 2015 Password Hashing Competition. Argon2id combines resistance to both GPU-based attacks (memory-hardness) and side-channel attacks. It allows configurable memory usage, iteration count, and parallelism. 

$argon2id$v=19$m=65536,t=3,p=4$c2FsdHZhbHVl$hashvalue...

🔐 scrypt

Strong

Designed by Colin Percival in 2009, scrypt is a memory-hard function that requires significant RAM to compute, making it expensive for attackers using specialized hardware (ASICs/FPGAs). Widely used in cryptocurrency and security applications. 

scrypt(password, salt, N=2^14, r=8, p=1, dkLen=32)

🔒 bcrypt

Proven

Based on the Blowfish cipher, bcrypt was introduced in 1999 and remains widely used. It includes a configurable cost factor that controls computation time, and it automatically generates and stores a salt with the hash.

Security Ethics

Understanding security tools and techniques comes with a responsibility to use that knowledge ethically and legally. This section outlines the key principles that should guide your approach to cybersecurity.

📜 Authorization

Never attempt to access, analyze, or test systems without explicit written authorization from the system owner. Unauthorized access to computer systems is illegal in most jurisdictions, regardless of intent. Always operate within the boundaries of your authorization.

📦 Data Minimization

Only collect, process, and store the minimum amount of data necessary for your authorized purpose. Avoid retaining sensitive information beyond its useful life. When working with hash analysis tools, never store lookup results containing plaintext values.

🎓 Protecting Student Data

Student credentials and personal data are protected by regulations such as FERPA (Family Educational Rights and Privacy Act) and GDPR (General Data Protection Regulation). Any tool that interacts with student data must comply with these regulations and institutional policies.

✅ Ethical Guidelines

  • Use security tools only for authorized, educational purposes.
  • Report vulnerabilities responsibly through proper disclosure channels.
  • Never use recovered credentials to access accounts or systems.
  • Respect the privacy and data rights of all individuals.
  • Document your activities and maintain an audit trail when performing security assessments.
  • Stay current with relevant laws, regulations, and institutional policies.
Remember: The knowledge gained from this platform is intended to help you understand and defend against security threats — not to exploit them. Ethical behavior is not optional; it is the foundation of professional cybersecurity practice.
