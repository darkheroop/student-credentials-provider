1. Project Overview

The Student Credentials Provider (SCP) is a production-grade educational web application engineered to teach core cybersecurity and software engineering principles:

  • Cryptographic digest characteristics versus mathematical two-way encryption.
  • Lookup database mechanisms (pre-computed rainbow tables and search indexes).
  • Secure client-server communication using RESTful JSON endpoints.
  • Resilient third-party API integration with rate limiting, timeouts, and credential isolation.
  • Defensive web programming techniques including strict server-side validation and security headers.
Core Educational Tenet: A student record lookup does not reverse a cryptographic one-way mathematical function; it performs an exact search across pre-computed database indexes.

3. Installation Instructions

Follow these steps to set up the development environment from scratch:

PowerShell / Bash
# 1. Navigate to the repository directory
cd "student-credentials-provider"

# 2. Create a Python virtual environment
python -m venv .venv

# 3. Activate the virtual environment
# Windows PowerShell:
.\.venv\Scripts\Activate.ps1
# Linux / macOS:
source .venv/bin/activate

# 4. Install all runtime and testing dependencies
python -m pip install -r requirements.txt

4. Environment Configuration

Configuration is managed via environment variables using python-dotenv. Copy the provided .env.example to .env in the project root:

.env Configuration
# Student Lookup Operating Mode: 'demo' (default) or 'live'
STUDENT_LOOKUP_MODE=demo

# External Provider Credentials (required only for live mode)
# Format: email:api_code as registered on md5decrypt.net
MD5DECRYPT_API_KEY=your_email@domain.com:your_api_code

# External request timeout in seconds
STUDENT_LOOKUP_TIMEOUT_SECONDS=10

# Per-client in-memory rate limiting (requests per minute)
RATE_LIMIT_PER_MINUTE=30

# Flask Security Key
SECRET_KEY=generate_a_random_32_byte_hex_string
Security Rule: The .env file is explicitly ignored in .gitignore. Never commit API keys or sensitive credentials to version control.

7. System Architecture

The application adheres to a clean layered architecture with complete separation of concerns:

Client Layer
Vanilla JS (ES6+) & Modern Semantic HTML5 UI
↓ JSON POST /api/student-lookup
Flask Application & Middleware
Rate Limiting, JSON Verification, Security Headers
↓ Validated Parameters
Student Lookup Service
Length / Hex Verification, Mode Routing (Demo vs. Live)
↙ Mode = Demo
Synthetic Dataset
Local In-Memory Student Records
↘ Mode = Live
External Provider Adapter
HTTPS GET, Sanitized Protocol Isolation

8. Four-Step Process Workflow

01

Submit

The user provides a hexadecimal lookup input and selects the corresponding algorithm from the interactive Student Lookup interface.

02

Validate

The client performs pre-flight checks, and the server validates digest length, character bounds (hex 0-9, a-f), and algorithm compatibility.

03

Query

The server routes the query either to the local synthetic dataset (demo mode) or securely queries the external database provider over HTTPS.

04

Interpret

The normalized response is structured and displayed with an educational explanation emphasizing the database search paradigm.

9. API Reference

The backend exposes RESTful JSON endpoints:

POST /api/student-lookup

Performs a student record lookup according to the active configuration mode.

Request Payload (JSON)
{
  "lookup_input": "5d41402abc4b2a76b9719d911017c592",
  "algorithm_type": "md5"
}
Success Response (HTTP 200)
{
  "success": true,
  "found": true,
  "status": "match_found",
  "lookup_input": "5d41402abc4b2a76b9719d911017c592",
  "algorithm": "md5",
  "plaintext": "hello",
  "mode": "demo",
  "duration": 0.0002,
  "message": "A matching entry was returned."
}
Not Found Response (HTTP 200)
{
  "success": true,
  "found": false,
  "status": "not_found",
  "lookup_input": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "algorithm": "md5",
  "plaintext": null,
  "mode": "demo",
  "duration": 0.0001,
  "message": "No matching entry was returned by the lookup service."
}
Validation Error Response (HTTP 400)
{
  "success": false,
  "status": "invalid_input",
  "error": "Invalid length for md5. Expected 32 characters, got 6.",
  "message": "Please provide a valid lookup value and supported algorithm."
}

POST /api/demo-student-lookup

Explicitly routes to the synthetic demo dataset, even if the server is configured in live mode. Never contacts the external network.

GET /api/health

Returns health check telemetry without exposing secrets or credentials.

{
  "status": "healthy",
  "mode": "demo",
  "service": "Student Credentials Provider",
  "version": "1.0.0"
}

11. Live Provider Mode Guide

To query the live external verification database:

  1. Register an account on md5decrypt.net.
  2. Retrieve your registered email and API key code.
  3. Set STUDENT_LOOKUP_MODE=live in your .env file.
  4. Set MD5DECRYPT_API_KEY=your_email:your_code.
  5. Restart the Flask server. The interface will switch from the purple DEMO banner to the cyan LIVE indicator.
Fail-Safe Principle: If live provider mode encounters an authentication failure, network timeout, or service error, the platform reports the exact live error state. It never silently falls back to demo mode.

12. Troubleshooting

❓ ModuleNotFoundError: No module named 'flask'

Ensure your virtual environment is activated and dependencies installed: python -m pip install -r requirements.txt.

❓ HTTP 429 Too Many Requests

You have exceeded the configured RATE_LIMIT_PER_MINUTE. Wait 60 seconds or increase the limit in .env for local benchmarking.

❓ Live Provider returns Authentication Error

Verify your MD5DECRYPT_API_KEY variable contains both your registered email and code separated by a colon (email:code) without spaces.

❓ Request Timeout

The external service took longer than STUDENT_LOOKUP_TIMEOUT_SECONDS to respond. Check internet connectivity or firewall rules.

13. Security Considerations

  • Zero Credential Persistence: Submitted lookup inputs and plaintext records are processed strictly in volatile memory. No disk persistence, database writes, or cache persistence occur.
  • Sanitized Diagnostics: Exception handling routines strip API keys, auth headers, and internal stack traces before responses leave the backend.
  • Defensive Headers: The server attaches Content-Security-Policy, X-Frame-Options: DENY, X-Content-Type-Options: nosniff, and Referrer-Policy: strict-origin-when-cross-origin.
  • DOM Injection Protection: Frontend code uses strict textContent and DOM node construction rather than raw innerHTML injection for untrusted inputs.
